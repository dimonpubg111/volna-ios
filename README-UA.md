# VOLNA Native 2.0 для iPhone та iPad

Це окремий нативний застосунок SwiftUI + AVKit для iOS 17+. WKWebView, JavaScript-сторінок та обгортки вебсайту в ньому немає. Сайт використовується лише як відкрите API каталогу, розкладу, відеореле й наявного архіву. Вхід у ChatGPT або Google не потрібний.

## Що реалізовано

- Чотири нативні вкладки: «Головна», «ТБ», «Фільми», «Моє».
- Liquid Glass на iOS 26; прозорі системні матеріали на iOS 17–18. Темний фон, кораловий акцент, системні переходи, анімація натискання, тактильний відгук. Налаштування зменшення руху та прозорості враховуються.
- Пошук каналів, жанри, обране, порядок Новий → ТЕТ → СТБ, відновлення останнього обраного каналу. У комплекті реальний каталог 155 українських каналів; запуск кожного з них на фізичному iPhone ще не перевірено.
- Вбудований AVPlayer, системний повний екран і автоматичне приховування керування, PiP та AirPlay для сумісних потоків. Торкання екрана обробляє AVKit. Немає окремої вебсторінки плеєра.
- Вибір аудіодоріжок і субтитрів лише тоді, коли вони надані джерелом. Показ справжньої роздільності після її визначення. Автоматичний бітрейт без штучного обмеження та економний режим до 1,5 Мбіт/с.
- Телепрограма: позавчора, вчора, сьогодні, завтра; час за Києвом. Збережена минула передача відкривається в тому самому плеєрі каналу. Майбутні передачі не запускаються. Неповні записи позначаються як фрагменти.
- Кеш списків записів окремо для ТЕТ/Нового каналу. Перехід на інший канал і тимчасова мережева помилка не очищають підтверджений список. Протерміновані записи старші за 48 годин відсіюються.
- Оновлення розкладу не замінює AVPlayerItem. Запис не перезапускається щохвилини разом із даними; повтор після помилки зберігає позицію. Буфер для записів більший, ніж для прямого ефіру.
- Мініпанель поточного перегляду при переході до інших вкладок; обране зберігається на пристрої.
- Пошук фільмів за назвою, альтернативними назвами, жанром і роком; сторінки з описами й постерами. Лише справжні HLS/MP4-джерела допускаються до AVPlayer.

## Важлива межа готовності

На цьому Windows-ПК немає macOS, Xcode та Apple SDK. **Проєкт не скомпільовано Apple-компілятором, не підписано і не запущено на iPhone чи симуляторі. ZIP — вихідні файли, не IPA.** Перевірка граматики Swift та структури проєкту не замінює компіляцію та перевірку на пристрої.

Великого каталогу популярних фільмів із прямим відео немає. Поточні 23 картки переважно мають тільки YouTube-джерела або відключене пряме джерело. У цій нативній версії такі фільми чесно позначені «Каталог» і не отримують неправдивої кнопки перегляду. Фільтр «Доступні» покаже лише реально підключені сумісні джерела. Застосунок не витягає приховані YouTube-потоки й не підміняє їх чужим плеєром.

Реклама, вже вставлена постачальником у відеопотік, може залишатися. Рекламних SDK та власних вставок застосунок не додає. Нова версія не змінює джерела каналів і не створює новий рекордер. Хмарний архів залежить від чинного тимчасового сервісу VOLNA та фактичної наявності записів. Його бюджет і строки не змінювалися.

Офлайн доступні метадані каталогу та локальне обране; відео для офлайн-перегляду не завантажується.

## Перевірки

На Windows виконано:

1. Розбір усіх 10 Swift-файлів граматичним парсером: без синтаксичних помилок.
2. Розбір OpenStep-проєкту Xcode, перевірку посилань файлів, трьох targets, shared scheme, Info.plist, privacy manifest і каталогу ресурсів.
3. Реальні HTTP-запити без авторизації до каталогу, загального розкладу, розкладу Нового каналу та списку архіву. Звіти — у комплекті `Verification/`.

Підготовлено, **але тут не виконано**: сім XCTest-перевірок моделей/часу/архіву/пошуку та один UI-сценарій з навігацією, пошуком, закриттям налаштувань і знімками екранів. Вони запускаються на macOS через `scripts/ci.sh`.

## Збірка без власного Mac: GitHub Actions

У корені архіву є `.github/workflows/ios.yml`. Потрібен власний GitHub-акаунт і репозиторій. Якщо завантажуєте через вебінтерфейс, перевірте, що прихована папка `.github` також потрапила до репозиторію.

1. Завантажте вміст папки `volna-ios` у корінь окремого репозиторію. Не завантажуйте ключі, сертифікати чи приватні файли.
2. Відкрийте Actions → VOLNA native iPhone → Run workflow.
3. Сценарій на стандартному `macos-26` перевірить проєкт, запустить модульні та UI-тести в симуляторі, потім скомпілює реліз для iPhone без підпису.
4. Результат: пакет для симулятора, **непідписаний** `.app` для пристрою, `VOLNA-2.0-UNSIGNED.ipa` для подальшого підписування та звіт `.xcresult` зі знімками UI-тесту. Непідписаний пакет не встановиться звичайним натисканням на iPhone.

Workflow запускається лише вручну. Для стандартних GitHub-hosted runners у публічних репозиторіях хвилини безкоштовні; зберігання артефактів має окремі квоти. Для приватних репозиторіїв застосовуються квоти акаунта. Самостійно репозиторій, оплату та публікацію коду в інтернеті не створено.

[Правила GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [macOS runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

## Встановлення на iPhone

Для справжнього застосунку потрібен підпис Apple. У проєкті немає чужих сертифікатів чи ключів.

Якщо є доступ до Mac із Xcode 26+:

1. Відкрийте `VOLNA.xcodeproj`, scheme `VOLNA`.
2. У target VOLNA → Signing & Capabilities виберіть свою Team, задайте власний Bundle Identifier.
3. Підключіть iPhone з iOS 17+, увімкніть Developer Mode, якщо Xcode попросить, і натисніть Run.
4. Безкоштовна Personal Team дозволяє особисте тестування, але профіль діє сім днів; потім потрібні повторна збірка й установлення.
5. Для звичайного поширення через TestFlight/App Store потрібна Apple Developer Program, підпис власника й процедура Apple. Облікові дані до вихідного коду не додавайте.

Хмарний Mac може замінити власний Mac для компіляції, але не скасовує підписування. Гарантованого довічного встановлення нативного IPA без Apple-підпису немає.

### Особисте встановлення з Windows

Є практичний шлях без власного Mac: після успішної хмарної збірки перепідписати отриманий IPA своєю Apple Account через офіційний AltServer/AltStore Classic для Windows. Це сторонній інструмент, а не сервіс Apple. Він використовує особистий обліковий запис для підписування; пароль вводиться лише в його локальній програмі й ніколи не додається в проєкт або чат. Установлення та продовження профілю цим способом тут не виконувались, тому на конкретному пристрої їх ще треба перевірити.

Безкоштовний профіль потребує оновлення кожні сім днів, а кількість активних застосунків обмежена. Коротка російськомовна інструкція — `Установка-на-iPhone-с-Windows.md`. **AltStore Classic відрізняється від AltStore PAL**; у цьому сценарії використовується Classic.

[Офіційна інструкція AltServer для Windows](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows), [установлення IPA та строки оновлення](https://faq.altstore.io/altstore-classic/your-altstore).

[Apple: Personal Team і строки профілів](https://developer.apple.com/help/account/basics/about-your-developer-account), [підготовка до поширення](https://developer.apple.com/documentation/Xcode/preparing-your-app-for-distribution).

## Файли

- `VOLNA/` — SwiftUI, AVKit, клієнт API, моделі, ресурси.
- `VOLNATests/`, `VOLNAUITests/` — тести для виконання в Xcode.
- `scripts/generate_project.py` — відтворюваний генератор Xcode-проєкту, який не переписує Swift-код.
- `scripts/ci.sh` — збірка й тестування на macOS з Xcode 26+.
- `scripts/validate_source.py` — попередня структурна перевірка; залежності в `scripts/requirements-validation.txt`.
- `Preview/` — ескіз оформлення, якщо додано; це не знімки запущеного iOS-застосунку.

Підключень сторонніх бібліотек, менеджерів пакетів, рекламних SDK і сервісів авторизації в застосунку немає. Privacy manifest вказує використання UserDefaults та часу зміни файлів лише всередині контейнера. Перед App Store потрібно ще перевірити декларації приватності й права на відеоконтент для обраного способу поширення.
